# MindBridge 操作与交接文档

更新日期：2026-09-21

## 1. 当前项目状态

当前主流程已经贯通：

1. 登录系统并进入 mPFC 科研工作区。
2. 从服务器发现的实验状态中选择数据。
3. 查看数据接入、智能分析、时间轴对齐和 3D 建模准备进度。
4. 对低可信或不一致片段进行人工复核。
5. 在 3D 工作区联动查看行为视频、神经活动和 EEG/EMG。
6. 选择至少两种状态进入多条件对比分析。
7. 勾选需要纳入报告的图表并生成统一报告。

默认 Provider 为 `precomputed`。它读取仓库内的预计算结果，并以任务接口形式向前端返回。`model` Provider 只保留了接口骨架，尚未接入真实推理服务。

## 2. 首次运行

在仓库根目录执行：

```bash
npm install
copy .env.example .env
npm run dev:full
```

浏览器打开 `http://localhost:5173`。默认本地账号为：

```text
用户名：admin
密码：MindBridge@2026
```

如果前端能打开但没有数据，依次检查：

1. `http://localhost:3001/api/health` 是否返回 `status: ok`。
2. `server/data/experiments/` 下是否存在三个条件目录及各自 `manifest.json`。
3. Vite 是否在 5173 端口运行，Express 是否在 3001 端口运行。
4. `.env` 中是否误把 `MINDBRIDGE_DATA_ROOT` 指向旧数据目录。

## 3. 正式演示操作

### 3.1 登录与数据选择

1. 在首页登录。
2. 进入“mPFC 科研工作区”。
3. 点击“选择实验数据”。
4. 未进入工作区的状态显示“开始处理”；已经导入的状态显示“打开工作区”。

### 3.2 数据处理与人工复核

处理页面按以下四段展示：

- 数据接入：行为视频、钙成像、EEG/EMG。
- 智能分析：行为视频识别、钙神经信号分析、EEG/EMG 睡眠分期。
- 时间轴对齐与复核准备：统一时间基准并定位待复核片段。
- 3D 建模数据：生成神经活动、动态功能连接和建模参数。

处理完成后进入人工复核。所有待复核片段处理完毕，才能确认最终状态标签并进入 3D 工作区。

### 3.3 3D 工作区

- 左侧视频显示当前行为状态。
- 左下信号面板用一张联动图呈现 EEG、EMG 和活动变化。
- 底部时间轴控制视频、信号和 3D 场景的同一时间点。
- 右侧 3D 视图显示神经元活动与功能共活动连接。
- “显示行为相关神经元组”用于突出当前行为高度相关的神经亚群；不再提供含义重复的 Top 3 模式。

对评委说明时应使用“功能共活动连接”，不要称为解剖连接或突触连接。

### 3.4 多条件比较与报告

1. 至少选择两个实验状态。
2. 在总览、行为与神经、功能网络或高级分析中点击“加入报告”。
3. 进入“报告”标签检查已选证据。
4. 点击“生成报告”。

同一个条件组合始终对应同一份生成报告：

- 两条件：`generated-compare_2.md`
- 三条件：`generated-compare_3.md`

再次生成会更新这份报告，不会按每个图表创建独立报告。所有已选图表集中写入报告末尾的“图表证据”章节，并附图表来源、内容和非专业读图提示。

## 4. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3001` | Express 端口 |
| `VITE_API_BASE_URL` | `/api` | 浏览器 API 前缀 |
| `MINDBRIDGE_DATA_ROOT` | `server/data` | 数据根目录；不配置时使用仓库数据 |
| `MINDBRIDGE_STATE_ROOT` | `server/state` | 复核、任务和报告运行状态 |
| `MINDBRIDGE_PIPELINE_PROVIDER` | `precomputed` | `precomputed` 或 `model` |
| `MINDBRIDGE_ADMIN_USER` | `admin` | 管理员用户名 |
| `MINDBRIDGE_ADMIN_PASSWORD_HASH` | 无 | scrypt 密码哈希 |
| `MINDBRIDGE_SESSION_SECRET` | 随机值 | 会话签名密钥；生产环境必须固定 |
| `MINDBRIDGE_SECURE_COOKIE` | `0` | HTTPS 环境设为 `1` |

生成密码哈希：

```bash
node scripts/hash-password.mjs "新的强密码"
```

把输出整行写入 `.env`，并另外设置足够长的 `MINDBRIDGE_SESSION_SECRET`。

## 5. 数据目录与版本约定

```text
server/data/
  experiments/
    _shared/                              跨条件共享的神经元位置等数据
    healthy/
    cort_like/
    ketamine_like_recovery/
      manifest.json
      raw/                                行为视频、钙成像、EEG/EMG
      versions/demo-v1/
        review/                           时间轴、预测与冲突数据
        visualization/                    3D 与图表数据
        model_output/                     行为相关神经亚群数据
  analyses/                               单条件与多条件分析 JSON
  reports/                                固定报告模板
```

新增实验状态时，必须同时提供 `manifest.json`、原始数据和版本目录。前端通过 `/api/experiments` 动态发现实验，不应在页面中硬编码新条件。

旧的 `raw_input/`、`review/`、`visualization_input/` 目录已迁移到上述版本化结构。后端仍保留旧 URL 的兼容映射，新代码应使用 `/api/artifacts/:artifactId`。

## 6. 验证与发布前检查

每次交付前至少执行：

```bash
npm run build
node --test server/tests/*.test.mjs
```

建议人工检查：

- 登录、退出和会话过期行为。
- 三个实验状态均可进入处理流程。
- 复核门禁必须在全部片段确认后放行。
- 视频、时间轴、信号和 3D 场景同步。
- 两条件和三条件报告均可下载。
- 浏览器控制台没有新增错误。

`scripts/verify-integration.mjs` 与 `scripts/verify-multi-condition.mjs` 是早期端到端脚本，部分选择器和旧流程名称可能已经过期；使用前先同步当前 UI 文案，不要直接把其结果当作发布结论。

## 8. 已知边界与下一步

- 当前只有一只小鼠的描述性比较，不能进行群体显著性推断。
- 三种状态是同一真实记录的文献约束重采样，应避免表述为真实独立给药实验。
- 真实 AI 推理服务尚未接入；接入时实现 `ModelPipelineProvider`，不要改前端 API 契约。
- 当前报告为 Markdown；图表章节记录图表标题、来源、图注和读图说明。若下一阶段需要带像素级图像的 Word/PDF，应增加统一的服务端图表渲染器，而不是在各页面分别截图。
- 端到端脚本需要按当前中文 UI 更新。

## 9. Git 交接建议

1. 从远程分支拉取后先执行 `npm install`。
2. 不提交 `.env`、`server/state/`、`dist/` 和运行时生成报告。
3. 数据结构变更时同时更新实验 `manifest.json`、API 类型和本操作文档。
4. 修改处理阶段名称时同步前端 `processingApi.ts` 与后端 `RUN_STAGES`。
5. 推送前查看 `git status`，确认旧数据目录的删除和新 `server/data/experiments/` 目录的新增同时存在，避免只提交迁移的一半。

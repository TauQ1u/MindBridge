## 1. 核心原则（先读这个）

**本包内的所有行为语义都是人工联动复核后的最终结果。**
上游的视频 AI 预测、神经解码预测、冲突标记停留在复核系统内部，
不进入本数据包。使用本包的同学不需要、也不应该看到模型之间发生过什么冲突。

当前复核流水线尚未接入 AI/神经解码模块，`provenance.json` 中每个条件的
`review_status` 均为 `baseline_accepted`，含义是"人工确认的初始基线标签"。
接入复核后该字段会变为 `human_reviewed`，包的字段结构不变。

## 2. 命名约定（三个维度，严禁混用）

| 维度 | 字段名 | 取值 |
|---|---|---|
| 实验/展示条件 | `condition_id` | `healthy` / `cort_like` / `ketamine_like_recovery` |
| 行为 | `behavior`（或 0/1 宽列） | `rearing` / `locomotion` / `motor` / `nesting` |
| 睡眠阶段 | `sleep_stage` | `W` / `NREM` / `REM` / `MA`（微觉醒） |

- 词 `state` 在本项目中**仅指行为/睡眠状态**，条件一律叫 `condition_id`
- `cort_like` / `ketamine_like_recovery` 是**文献约束的虚拟重采样条件**，
  不是真实给药实验；禁止在展示文案中写成"注射 CORT 后实测"

## 4. 主时钟（唯一公共参照系）

对齐只需要一个锚点 + 三个采样率。`final_label_timeline.csv` 的**每一行就是主时钟的一格**
（`time_seconds` 给出该格时间 `t_i`），任意一格的三个模态位置是纯算术：

| 模态 | 采样率 | 第 i 格位置 |
|---|---|---|
| 标签 / Ca²⁺ | 1.9231 Hz（0.52 s 格） | 行号 i 本身 |
| 视频 | **15 fps**（重编码，源 AVI 为 30 fps） | `[floor(t_i×15), floor(t_{i+1}×15))` |
| EEG/EMG | 1000 Hz | `[floor(t_i×1000), floor(t_{i+1}×1000))` |

表中已直接给出三列，无需自己算：
`video_frame_start`、`eeg_sample_start`、`eeg_sample_end`（均为左闭右开区间的起点/终点）。

前端展示视频、画 EEG 波形、跳转到任意帧，**全部只查这一张表**。

### `final_label_timeline.csv` 列说明

| 列 | 说明 |
|---|---|
| `frame` | 主时钟整数索引（0 起） |
| `time_seconds` | 该格时间（片段内相对秒） |
| `condition_id` | 条件 |
| `behavior` | 主行为标签。派生优先级：rearing > locomotion > motor > nesting > quiet_wake；睡眠帧直接取睡眠阶段（NREM/REM/MA） |
| `sleep_stage` | W / NREM / REM / MA |
| `seam_before` | **拼接缝标记**：true 表示该格是三个真实片段（A 活动/B 睡眠/C 筑巢）的人工拼接点，不得解释为真实生理转移；跨缝的序列分析/动画过渡应跳过 |
| `rearing` `locomotion` `motor` `nesting` | 原始 0/1 行为列（与 behavior 一致的 ground truth 宽表） |
| `video_frame_start` `eeg_sample_start` `eeg_sample_end` | 主时钟对齐列（见上） |

### `calcium.csv` 列说明

`frame_idx, time_seconds, n1 … n117`（693 行 × 119 列，约 1.6 MB/条件）。
单元格 `[i][n{k}]` = 第 k 个神经元在第 i 个主时钟格的 ΔF/F。原始 HDF5 中的对齐关系是
`dff 列 i == labels.csv 行 i`，本副本按 frame-major 转置以便直接读取。
展示包只带这一份轻量副本；如需全量数据（如 eeg_emg.h5 四通道 × 36 万采样点），找数据组另取。

### `dynamic_edges.csv` 与 `neuron_positions.csv`（动态功能连接）

**`neuron_positions.csv`（包级，三条件共享）**：117 个神经元的**真实 2D ROI 中心坐标**，
来自上游 `Calcium imaging_Trace.mat` 的 `center`（不是随机生成位置）。
列：`neuron_id, neuron_name, x, y, z, x_norm, y_norm, z_norm, z_anatomical, snr, snr_norm`。

**关于 z 与 module_id（核心方法，全包唯一一套、三条件共用）**：

上游是单平面钙成像，`center` 只有 (x, y)，**原始数据集不存在解剖深度**。本包的
第三维是**功能纵深**，由 `scripts/build_functional_layout.py` 从全记录 25.11 h 真实
ΔF/F 计算（方法完整记录在包级 `layout_method.json`，含源数据 sha256 与全部参数）：

1. W = 全记录 117×117 |Pearson|（不用 top-30 边表，避免采样偏差），稀疏化为对称 kNN 图（k=12，并集规则）
2. 图拉普拉斯谱嵌入取前 3 个特征向量；z 方向 = 与 ROI 的 x/y 相关性最小者（|corr| = 0.049 / 0.025，冗余极低）
3. z 按中位数中心化归一化到 [-1, 1]；`z_anatomical=false` 逐神经元标记"非解剖测量"
4. 模块 = 谱聚类；k ∈ 3..8 由 **eigengap 筛选 + silhouette + 重采样稳定性（对半切 + 20 次时间块 bootstrap 的 ARI）** 共同决定，选中 **k\* = 3**（模块大小 58 / 22 / 37）
5. **模块只做颜色/包络/质心/群组高亮，不做 z 排序**（功能模块没有序数关系）

稳定性如实说明：k=3 的 mean ARI = 0.554、min ARI = 0.307——模块结构**中等偏弱但真实**
（钙成像功能连接噪声本就大），展示文案不应宣称"存在三个界限分明的功能群"。
另：两个模块在 z 轴上天然重叠（重叠信息由颜色承担），这是数据事实，不是错误。

## 5. 数据如何服务 3D 建模（渲染语义对照表）

| 视觉量 | 数据来源 | 语义 |
|---|---|---|
| X | `neuron_positions.x`（ROI 像素坐标） | 二维空间位置 |
| Y | `neuron_positions.y` | 二维空间位置 |
| **Z** | `neuron_positions.z` | **功能纵深**（谱嵌入坐标，非解剖深度；三条件共用、永不随时间变） |
| 球颜色 | `module_id` | 神经功能群（3 个） |
| 球亮度/大小/glow | `calcium.csv` × `activity_norm.json` | 当前活动强度（动态视觉编码，**不进坐标**） |
| 连线 | `dynamic_edges.csv` | 当前功能连接（correlation/weight，30 条/帧） |
| 线宽/亮度 | \|correlation\| | 连接强度 |
| 时间轴/行为 | `final_label_timeline.csv` | 主时钟 + behavior + seam_before |

**活动归一化（前端照做，不要自己 min-max）**：
`a'(t) = clip((a(t) − P5) / (P95 − P5), 0, 1)`，P5/P95 已按全记录算好放在
`activity_norm.json`（逐神经元），防止单个异常峰值压暗 99% 的活动。
亮度/半径建议：`brightness = f(a')`，`radius = r₀ + α·a'`（a'=0.1 小且暗，0.9 大、高亮、halo）。

**呼吸扰动（可选）**：`z_i(t) = z_i + ε·a'_i(t)`，ε < 0.1 × Z_range，只产生轻微浮动，
基础空间关系不动，避免误读为神经元在脑组织内移动。

**跨条件可比性**：三个条件的神经元基础坐标（x, y, z）**完全相同**——因为本来就是同一批
117 个 ROI。条件间只允许模块归属、活动强度、连接网络发生变化；旋转对比时看到的
任何结构差异都来自数据，不来自布局算法。

**拼接缝**：`seam_before=true` 的主时钟格是 A|B|C 片段人工拼接点，跨缝的连线动画/
序列过渡应跳过，不得解读为真实生理转移。

**`dynamic_edges.csv`（每条件约 2.1 万行）**：标准 edge-list，列与参考实现完全一致：
`frame, timestamp, behavior, source, target, correlation, weight,
window_start_frame, window_end_frame, window_size`

计算方法（每条件 `metadata.json` 中有同样记录）：

| 项 | 值 |
|---|---|
| 方法 | 滑窗 Pearson 相关，窗内真实 ΔF/F |
| 窗长 | 10 帧 ≈ 5.2 s（1.9231 Hz；参考实现为 24 帧 @ 4.8 Hz = 5.0 s） |
| 窗语义 | `start = max(0, t-9), end = start+9`，全程落在片段内（与参考实现一致） |
| 方向 | 无向（每对神经元只出现一次） |
| 权重 | `weight = abs(correlation)`，符号保留在 `correlation` 列 |
| 每帧保留 | \|r\| 最大的 30 条边 |

**解读红线：这是动态功能连接 / 活动相关网络，不是解剖连接，更不是突触连接。**

前端 join keys（与参考实现同款）：
- `calcium.csv` 的 `n1..n117` 列 ↔ `neuron_positions.csv` 的 `neuron_name`
- `dynamic_edges.csv` 的 `source`/`target` ↔ `neuron_positions.csv` 的 `neuron_name`
- `dynamic_edges.csv` 的 `frame` ↔ `final_label_timeline.csv` 的行序

### `behavior_stats.json`

每条件的活动统计：总时长、帧数、`behavior_fraction`（主标签占比）、
`behavior_columns_fraction`（四个行为列各自占比）、`sleep_stage_fraction`、
`seam_count`、`review_status`。

## 5. 每个条件的构成（约 360 s = A 150 s + B 120 s + C 90 s）

- **A 活动段**：rearing（≥3 次事件）+ locomotion + motor + W
- **B 睡眠段**：NREM + REM + MA（方向约束参照 Gong 2023 等 CORT 睡眠文献）
- **C 筑巢段**：nesting + W
- 三个条件共用同一套真实源数据，仅片段选择与排列不同；拼接缝即 A|B、B|C 边界
